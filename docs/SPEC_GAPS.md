# Specification gaps

**What this is.** Every place the design documents did not answer a question the build had to
answer. A gap is not a defect in the build, it is a silence in the specification, and a silence
never fails a check, which is why it needs its own log.

**Why it is not only a gate 7 document.** A gap found at stage 4 has to be visible at gate 4,
while amending the specification is still cheap. By gate 7 the data is generated and the silence
has already been resolved by whatever guess was made. So this file is rewritten at every gate.

**Two kinds of entry.** The block below is generated: holes, unsourced values and undeclared keys
are all machine-detectable. Everything after it is hand-written, because a silence that was
resolved by reading v1's code can only be recorded by whoever read it.

### SG1. The training half has no provenance register (15 Aug 2026)

**The silence.** The generator half has `t9_sim/calibration/provenance_table.md`, 50 rows of
parameter, value, route and source. The scoring half has no equivalent in any document.

**What was done.** v1's code and `docs/v1/T9Sim_Config_Reference.md` were read to recover 8
values: the historical-price switch state, the encoder shrinkage, the bid ladder, 3 XGBoost
parameter sets, and the attribution sample count and seed. All are routed `inferred` with a v1
citation. Evidence trail in `docs/T9Sim_Hole_Provenance.md`.

**What would close it.** A training-side provenance table in the specification, so v2's scoring
settings stop being recoverable only from v1.

### SG2. The specification never states the archetype tilt strengths (15 Aug 2026)

**The silence.** Open item O1 wired archetype into os, device type and day of week. No document
says how strong those tilts should be, and no outside dataset can say, because archetype is T9's
own latent.

**What was done.** Invented and declared under O3 3b, as one dial per table on a shared ladder,
with tau = 0 reproducing a parentless draw exactly. v1's own `bn_cpts.yaml` was read afterwards
and disagreed on the day-of-week sign, which corrected the decision.

**What would close it.** Nothing external can. The values stay `inferred` and the datasheet
declares them.

### SG3. Two live SHAP paths disagree on sample size (15 Aug 2026)

**The silence.** No document states the attribution sample count. v1's code has 2 answers,
`pipeline.py:774` at 3000 and `scripts/v10_shap.py:82` at 4000.

**What was done.** Took 4000, the path behind the reported v10 figures.

**What would close it.** The specification stating the count, and a note on which path produced
the published SHAP figures.

### SG4. `plate` and `edge_group` are decided in code, not in a document (15 Aug 2026)

**The silence.** Every node has a `plate`, how often it is drawn, and an `edge_group`, which random
stream it draws from. Neither is stated per node in the node register, and the specification never
defines what a family is or why there are 9 of them.

**What was done.** `tools/build_graph.py` infers both from the register's `### 3.x` family heading
through 2 lookup tables inside the script, `FAMILY_PLATE` and `FAMILY_STREAM`. So 2 structural
properties of all 78 nodes are decided by a Python dictionary rather than by a design document.

**Why it matters.** The stream decides reproducibility: a node in the wrong stream shifts other
nodes' draws when it changes. The plate decides how often a value is redrawn, so the wrong plate
silently changes the correlation structure of the whole dataset. Neither error would fail a check.

**CLOSED 16 August 2026, and more strongly than proposed.** The suggestion was a 9-row family table.
What was done instead is a `Plate` and a `Stream` column on all 78 register rows, stated per node
rather than per family, and `build_graph.py` now READS them and only validates the vocabulary.
`FAMILY_PLATE` and `FAMILY_STREAM` are deleted.

Per node rather than per family because the family inference was already wrong: it gave B1 an app
plate while its parent `app_i` sits at auction plate, a backwards edge no check could see, because
nothing read plate. A family table would have reproduced that error, since the error was in treating
the family as the unit.

The acceptance test was that `graph.yaml` regenerate byte-identical from the stated values, which it
did, so the 78 stated plates and streams reproduce the inferred ones exactly and the one node that
disagreed was the defect.

### SG5. The archetype tilt strengths cannot be checked by any gate (15 Aug 2026)

**The silence.** No document states how strongly archetype should tilt os, device type or day of
week, and no outside dataset can, because archetype is this project's own latent: nothing published
holds an archetype-by-os cell.

**What was done.** Invented and declared under open item O3 3b: one dial per table on a shared
archetype ladder, tau = 0.13 for os and device, 0.04 for day of week, all route `inferred`.

**Why it needed more than declaring.** Each table is raked, so its marginal survives whatever tau is.
0.13 and 0.26 produce identical calibration rows and identical direction checks. **No gate in the
build can tell a right value from a wrong one**, which makes these the only invented numbers here with
no test attached.

**The mitigation, and its limit.** A 4-arm sensitivity sweep, tau x {0, 0.5, 1, 2}, 3 paired seeds at
100K. It runs before the campaign so it can still change the decision. It establishes whether the
headline contrasts depend on tau. It cannot establish that 0.13 is right, and nothing can.

**IT HAS NOW RUN, 16 August 2026 at stage 4.** 4 arms x 3 seeds at 100K, `tools/tilt_sweep.py`, full
record at `docs/gates/tilt_sweep.json` and the table in `docs/gates/gate4.md`.

| Contrast | tau x0 | tau x0.5 | tau x1 | tau x2 |
|---|---:|---:|---:|---:|
| MMP, click AUC (C2 - C1) | +0.09810 | +0.10969 | +0.10291 | +0.09074 |
| SSP, win AUC (C3 - C1) | -0.00114 | +0.00067 | +0.00050 | -0.00066 |
| MMP, ev_ratio (C2 - C1) | +0.15278 | +0.10799 | +0.12294 | +0.10487 |
| SSP, ev_ratio (C3 - C1) | -0.00669 | -0.00095 | -0.00246 | -0.00301 |

**The finding: no headline contrast moves more than 2 seed standard deviations from its value at the
chosen tau, across the whole range.** The MMP result is large and steady at every arm. The SSP result
is near zero and sign-unstable at every arm, which is a fact about this build's Tier 2 rather than
about tau, and it is the same at tau = 0 where no tilt exists at all. **So the conclusions do not
depend on the invented strengths**, which is exactly what this gap needed and the only thing a sweep
can give it.

The tau = 0 arm also reproduces a generator built with the 3 tilt tables removed entirely, bit for
bit, compared against a build made from the marginal with no ladder and no rake. The wiring is a true
no-op at zero rather than approximately one, so the null arm is a real null.

**What would close it.** Nothing external, and nothing has changed about that. The values stay
`inferred` and the datasheet declares them. What the sweep buys is not confidence in 0.13; it is
evidence that 0.13 does not matter to the answer.

### SG6. Nine settings the generator cannot run without had no home at all (16 Aug 2026)

**The silence.** Specification 2.0 states that `config/profiles.yaml` carries "rho, seeds, scales,
`block_rows`, the four pool sizes". It carried the first four and no pool sizes. `n_users`, `n_apps`,
`n_campaigns` and `n_advertisers` existed in no v2 settings file, while `pair_idx`'s own law decodes
its drawn cell by integer division over `n_apps` and rows B1 and C1 cite `profiles.<p>.n_apps` and
`profiles.<p>.n_advertisers` directly. Six more were in the same state: `advertiser_share` (which
`adv_tier` draws from), `campaign_share` (which `sample_weight` is derived from), `ad_exchanges` (B3),
`slot_format_shares` (B6) and both halves of `slot_quality` (`v_slot`).

**How it survived gate 1.** `tools/report_holes.py` kept only backticked tokens containing a dot, so
every key cited by its bare name was invisible to it. All seven are cited bare. The audit therefore
printed **0 undeclared** against a configuration that could not have generated a single row.

**What was done.** The values were recovered from v1 with their provenance intact and written to
`profiles.yaml` (`default.pool_sizes`, the three v1 rungs carried whole, the 200K golden-test rung
derived from v1's own stated 4.5-auctions-per-user rule and marked as derived) and to `market.yaml`
(`advertiser_scale.advertiser_share` and `.campaign_share`, and a new `context` block holding
`ad_exchanges`, `slot_format_shares` and `slot_quality`). The detector's filter was widened to
consider bare snake_case keys, screened against node ids and emitted column names so it does not
report the register's own vocabulary back at itself. It now finds the class: it went from 0 to
catching all nine before they were written.

**What would close it.** Nothing outstanding. Noted here because the failure mode is the interesting
part: the check reported clean because of what it could not see, not because there was nothing there.

### SG7. `lognormal_mu` was cited as a settings key and is a solver output (16 Aug 2026)

**The silence.** The register and two comments, in `market.yaml` and `validation.yaml`, all name
`market.yaml ltv.lognormal_mu`. No such key exists, and it must not: it is solved against the $6
median, so putting it in the hand-written layer would place a fitted number among the design ones.
`calibrated.yaml` was empty pending stage 2, so the constant had no home anywhere and read as a gap.

**What was done.** `calibrated.yaml` now carries the solver's **output contract**: the 8 keys stage 2
must write and the target each is solved against, names only and no values. The provenance of an
auto-calibrated value is its target and its procedure, so the targets are the part worth fixing in
advance.

**Settled 16 August 2026, and it was a ninth constant.** v1's provenance table records
`ltv.lognormal_sigma` at `t9_sim/calibration/provenance_table.md:12` as SOLVED by autocal against the
whale top-5-percent share target 0.55-0.65. v2 had inherited the solved number, 1.648169, without the
record and routed it `specified`, which claimed a design document stood behind a fitted value.
`market.yaml` now routes it `auto-calibrated` with that target. The contract briefly listed 9 and
then settled at 6, because the 3 archetype LTV means left it the same day: they were routed
`auto-calibrated` while no solver had ever produced them, and all 3 plus sigma aim at the single
top-5-percent scalar, so only sigma is identified. They are now `inferred` and held at v1's values.
The rebuild
plan's "8 constants" was corrected. v1's analytic starting point, sqrt(2 x ln(25/6)) = 1.6889, is kept
in the source string as the value the autocal refined.
